1. INTRODUCTION                                        *lvim-calendar-intro*

lvim-calendar is a calendar panel built on the canonical lvim-ui surface
chassis: four views (month, quarter, year, agenda) over one date model and
one cell renderer, Emacs-grade date navigation, and day DECORATIONS coming
from pluggable SOURCES — the seam org- and markdown-note systems plug into
without the calendar knowing about them.

Selecting a day either resolves a consumer callback (a date picker for other
plugins' forms) or inserts the formatted date into the buffer the calendar
was opened from.

==============================================================================
2. REQUIREMENTS                                 *lvim-calendar-requirements*

Neovim >= 0.10, lvim-ui (the surface chassis) and lvim-utils (palette,
self-theming, cursor management).

==============================================================================
3. SETUP                                               *lvim-calendar-setup*

Call setup() to merge options, bind the highlights, register the built-in
sources and the |:LvimCalendar| command. The full defaults: >lua

    require("lvim-calendar").setup({
        view = "quarter",          -- month | quarter | year | agenda
        layout = "float",          -- float | area | bottom
        first_day = "monday",      -- monday | sunday
        week_numbers = false,      -- ISO week numbers per grid row
        insert_format = "%Y-%m-%d",-- os.date format for the <CR> insert
        source_timeout_ms = 30000, -- un-wedge an async source that never calls done() (0 = off)
        agenda = {
            span = "week",         -- day | week | fortnight | month
            show_empty = false,    -- show day sections without entries
        },
        holidays = {},             -- built-in holidays source input
        dates = {},                -- built-in user dates source input
        org_diary = {              -- built-in org-diary source (off by default)
            enabled = false,
            dir = "~/Org/diary",
        },
        keys = {
            prev_day = "h",   next_day = "l",
            next_week = "j",  prev_week = "k",
            prev_month = "H", next_month = "L",
            next_year = "J",  prev_year = "K",
            week_start = "0", week_end = "$",
            today = { "t", "." },
            next_mark = "w",  prev_mark = "b",
            goto_date = "gd", cycle_view = "v",
            select = "<CR>",  create = "i",
            help = "g?",      -- the keymap CHEATSHEET
        },
        content_border = nil,      -- nil inherits the shared lvim-ui content ring
        agenda_colors = {          -- agenda row striping (accents + tint strengths)
            odd = "blue", even = "yellow", header = "blue",
            tint = 0.05, active_tint = 0.1, lead = 0.1,
        },
        icons = {
            title = "󰃭",      -- panel border-title glyph
            holidays = "",    -- holidays source lead icon
            dates = "󰃶",      -- dates source lead icon
            mark = "•",       -- default decorated-day mark
        },
    })
<
`holidays` entries are `{ date, title }` — "MM-DD" recurs every year,
"YYYY-MM-DD" is a single occurrence. `dates` entries are
`{ date, title, time?, mark?, file?, line? }`; `file`/`line` make the agenda
<CR> jump there.

4. VIEWS                                               *lvim-calendar-views*

month~
    One full month grid: weekday header, optional ISO week numbers,
    other-month padding dimmed, weekends tinted, today and the cell cursor
    highlighted, decorated days carrying their source mark.

quarter~
    The Emacs calendar strip — previous / CURRENT / next month side by side.
    The cursor month is always the center block, so moving past an edge
    re-centers the strip.

year~
    12 compact mini-months in a responsive grid (4 columns when the editor
    is wide enough, else 3). Marks collapse to a dot. <CR> picks the day
    under the cursor, exactly as in the month and quarter views.

agenda~
    A date-anchored entry list over a span (day / week / fortnight / month;
    its own filter band): one section per day, rows = source icon + time +
    title. Empty days are elided unless `agenda.show_empty`. <CR> opens the
    entry (source `on_open`, else `edit file` + line).

The header carries the view filter band ([m]onth Q[u]arter [y]ear [a]genda),
the agenda span band, and a `‹ Month Year ›` / today nav band; the
month-year button opens a quick-jump (month picker, then a year prompt).
CTRL-J / CTRL-K move between the bands, the grid and the footer.

==============================================================================
5. PANEL KEYS                                           *lvim-calendar-keys*

    h / l            one day back / forward
    j / k            one week forward / back (agenda: next/previous entry)
    H / L            one month back / forward
    J / K            one year forward / back
    0 / $            start / end of the cursor week
    t / .            today
    w / b            next / previous decorated day (a day with entries)
    gd               goto date (see below) — a CHORD under the `g` prefix (a
                     bare `g` cannot coexist with the `g?` cheatsheet chord)
    g?               the keymap CHEATSHEET (also a `help` chip on the footer)
    v                cycle month → quarter → year → agenda
    m u y a          switch the view directly (month / quarter / year / agenda)
    d W f M          agenda span: day / week / fortnight / month
    <CR>             confirm the day (every grid view) / open the agenda entry
    i                create an entry (source on_create; chooser when many)
    q / <Esc>        close

The goto-date prompt accepts absolute dates ("2026-07-06", "06.07",
"6.7.2027"), relative offsets ("+3d", "-2w", "+1m", "-1y") and "" / "t" for
today.

Mouse ~
Left-click a day in the grid (month / quarter / year) to land the cursor on it,
exactly as the arrow keys do (same day-change event + repaint); in the agenda,
click an entry row to select it. The header filter / span / nav bands and the
footer actions are click targets too. A click is a no-op while 'mouse' is empty.

6. SOURCES                                           *lvim-calendar-sources*

                                             *lvim-calendar.register_source()*
require("lvim-calendar").register_source({spec})
    Register an entry source: >lua

        require("lvim-calendar").register_source({
            name = "org-notes",     -- unique id
            icon = "",             -- agenda lead glyph
            accent = "green",       -- palette color: day tint + lead box
            get = function(range, done)
                -- range = { from = "2026-07-01", to = "2026-07-31" }
                -- return entries synchronously, or call done(entries)
                return {
                    { date = "2026-07-06", title = "standup",
                      time = "09:30", file = "~/notes/x.md", line = 12 },
                }
            end,
            on_open = nil,          -- entry → custom jump
            on_create = nil,        -- (date) → new entry (the `i` key)
        })
<
    `get` is called ONCE per visible range (batched, never per day); results
    are cached per (source, month). Async replies are generation-guarded: a
    reply arriving after |lvim-calendar.refresh()| bumped the generation is
    dropped. Entries may override `mark` / `hl` per entry.

Built-in sources `holidays` and `dates` are registered by setup() from the
config tables and double as reference implementations.

                                                  *lvim-calendar-org-diary*
`org_diary` is the third built-in, off by default. Turn it on with the
directory the diary lives in: >lua
    require("lvim-calendar").setup({
        org_diary = { enabled = true, dir = "~/Org/diary" },
    })
<
It reads orgmode's own layout — a YEAR/MONTH/DAY tree, `<dir>/2026/01/16.org`,
one file per day — so a day's DATE comes from its PATH, not from a file name.
An entry's title is that file's first org heading (`Diary` when it has none);
creating an entry on a day opens that day's file, making the YEAR/MONTH
directories on the way; and saving a diary file re-decorates its day at once,
without waiting for the panel to be reopened.

7. API                                                   *lvim-calendar-api*

                                                       *lvim-calendar.open()*
require("lvim-calendar").open({opts})
    Open the panel. {opts}: `view`, `layout` (session-sticky), `date`
    ("YYYY-MM-DD" or `{ y, m, d }`), `on_select(date)`.

                                                      *lvim-calendar.close()*
require("lvim-calendar").close()
    Close the panel when open.

                                                       *lvim-calendar.pick()*
require("lvim-calendar").pick({opts})
    Date-picker convenience for other plugins' forms: opens the calendar
    (month view by default) and resolves the picked day through
    `callback(date)`.

                                                    *lvim-calendar.refresh()*
require("lvim-calendar").refresh({name})
    Drop cached entries (one source, or all with no argument), bump the
    generation and repaint an open panel. Call it after writing a note file.

                                                *lvim-calendar.entries_for()*
require("lvim-calendar").entries_for({date})
    All entries on one day ("YYYY-MM-DD"), merged across sources and sorted
    by time.

                                         *lvim-calendar.dates_with_entries()*
require("lvim-calendar").dates_with_entries({range})
    Sorted unique dates carrying at least one entry inside the inclusive
    `{ from, to }` ISO range.

                                                      *lvim-calendar.model*
require("lvim-calendar").model
    The pure date-math module (grids, shifts, ISO weeks, parsing) —
    re-exported for consumers computing ranges.

==============================================================================
8. EVENTS                                             *lvim-calendar-events*

All fired as |User| autocommands:

    LvimCalendarOpen     the panel opened; data = { date, view }
    LvimCalendarClose    the panel closed
    LvimCalendarDay      the cell cursor landed on a day;
                         data = { date, entries } — the live-preview seam

==============================================================================
9. COMMAND                                           *lvim-calendar-command*

                                                             *:LvimCalendar*
:LvimCalendar [view] [layout]
    Open the calendar. A view token (month|quarter|year|agenda) and/or a
    layout token (float|area|bottom), in any order; both tab-complete. A
    layout given here is sticky for the session; `layout` in setup() is the
    cross-session default. Registered by setup().

==============================================================================
10. HIGHLIGHTS                                    *lvim-calendar-highlights*

Self-themed from the lvim-utils palette (re-derived on ColorScheme /
palette sync), overwritable by a colorscheme:

    LvimCalendarHeading            month/year headings (blue bold)
    LvimCalendarWeekday            weekday header (dim)
    LvimCalendarWeeknum            ISO week numbers (dim)
    LvimCalendarDay                a plain day cell
    LvimCalendarFaded              other-month padding cells
    LvimCalendarWeekend            Saturday/Sunday cells (red tint)
    LvimCalendarToday              today (blue tint, bold)
    LvimCalendarCursor             the cell cursor (yellow tint; wins)
    LvimCalendarMark               decorated-day fallback
    LvimCalendarMark<Source>       per-source day mark
    LvimCalendarLead<Source>       per-source agenda lead box
    LvimCalendarAgendaHeader       agenda day-section headers
    LvimCalendarAgendaRowB/Y       agenda entry rows (striped)
    LvimCalendarAgendaRowActiveB/Y the active agenda row
    LvimCalendarEmpty              "no entries" placeholders

11. HEALTH                                            *lvim-calendar-health*

                                              *:checkhealth-lvim-calendar*
:checkhealth lvim-calendar
    Reports the lvim-ui / lvim-utils base, verifies every configured glyph
    is single-width (the fixed cell boxes require it), and lists each
    registered source with its cache state (months cached, generation).
